## 1. Sprint Goal

The main goal of Sprint 5 was to finalize the Aysan Luxury Hotel Booking System by testing the implemented features, fixing remaining defects, checking database integrity and security, verifying website responsiveness and browser compatibility, and preparing the project documentation and final demonstration.

The team focused on ensuring that the completed system met the agreed acceptance criteria and that the main user workflows worked correctly. Any unfinished user stories from previous sprints were also reviewed and prioritized according to their importance and the team's remaining capacity.

## 4. Testing and Quality Assurance

The team reviewed the quality of the final product through functional testing, validation testing, database checks, responsive-design checks, and defect retesting.

### 4.1 Testing activities

- Test the main website pages and navigation links.
- Check that room descriptions, photos, and prices display correctly.
- Test booking forms using valid, missing, and invalid information.
- Verify that booking records are stored and retrieved correctly when database functionality is implemented.
- Check that unsuccessful operations do not display misleading success messages.
- Test the contact form and its actual submission behavior.
- Check the layout on different screen sizes and available browsers.
- Retest fixed defects and document any remaining issues.

### Lessons learned
- Testing should be performed throughout development rather than postponed until the final sprint.
- Clear communication and task ownership help reduce integration problems.
- Acceptance criteria make it easier to determine whether a feature is complete.
- Final reports should reflect verified implementation and test results.

 

## 9. Final Recommendations

1. Resolve any remaining critical defects before presenting the project.
2. Verify the booking workflow from entering information through the actual submission result.
3. Protect database credentials and validate user input appropriately.
4. Keep documentation consistent with the implemented system.
5. Clearly explain any limitations during the final demonstration.
6. Record future enhancements separately from features included in the completed scope.
